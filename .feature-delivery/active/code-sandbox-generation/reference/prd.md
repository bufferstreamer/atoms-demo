# CHG-010 Code Sandbox Generation PRD

> 状态：`SCOPE_FROZEN`。冻结只表示产品范围稳定，不表示代码已实现；CHG-010-DESIGN-REVIEW-001 仅细化技术与追踪契约，未扩大产品范围。

## 1. 来源与目标

原挑战要求智能体驱动完成代码或应用生成、可视化展示、真实交互、数据持久化和公网可用。生产反馈证明 AppSpec 白名单只能生成有限看板，计数器需求连续失败后返回无关 `Spark 项目看板`。本期目标是把核心生成物升级为可检查、可运行、可版本化的纯前端代码包，同时保留现有工作台、Agent 过程、D1 项目链路与公网交付。

目标用户是评委或体验者。完成结果必须让用户输入计数器、Todo、计算器、落地页等不同需求，得到与需求一致的 HTML/CSS/JavaScript 应用，在隔离预览中真实操作，并能通过刷新恢复应用数据。

## 2. 用户场景

| Requirement | 用户/前置 | 操作 | 预期结果 | 异常结果 |
| --- | --- | --- | --- | --- |
| FR-001 | 首次访问者 | 在想法输入框描述应用 | 保留当前 idea-first 工作台，展示 Agent 阶段和预览 | 输入为空、过长或超限时原位提示 |
| FR-002 | 合法需求 | 开始生成 | AI 返回真实 `CodeBundle v1`，至少包含 HTML、CSS、JavaScript，代码与需求语义一致 | 模型/协议失败不创建无关版本 |
| FR-003 | 已生成代码包 | 在预览中点击、输入或提交 | 自定义 DOM、样式、状态和事件逻辑在隔离沙箱中执行 | 运行错误显示错误卡并保留代码/上一版本 |
| FR-004 | 生成应用调用 `Atoms.storage` | 修改业务数据并刷新 | 服务端按 owner/project 持久化 JSON 状态，刷新后恢复 | 非法 key、超大 value、越权项目被拒绝且不写入 |
| FR-005 | 已有项目 | 继续描述修改、查看 Agent 过程、切换历史版本 | 创建不可变新代码版本；旧版本可查看；旧 AppSpec 项目仍可读取 | 过期基线或并发修改保持当前版本不变 |
| FR-006 | 模型或校验失败 | 等待生成结束 | 明确展示失败阶段、可公开错误原因和重试入口 | 禁止把固定模板作为成功结果写入 |
| FR-007 | 已生成代码 | 切换“预览/代码” | 可查看三类代码文件；预览只执行受控纯前端能力 | 外链、危险 API、路径穿越或超限包被服务端拒绝 |
| FR-008 | 输入计数器基准需求 | 生成后点击 `+1`、`-1`、重置并刷新 | 数字按操作变化，刷新恢复最后值，标题/控件与需求一致 | 任一动作、恢复或语义不符即验收失败 |
| FR-009 | 访问工作台 | 查看产品边界和生成来源 | 页面明确“纯前端沙箱”、模型来源、失败阶段和是否降级 | 不使用“任意全栈”误导用户 |

## 3. 页面与交互

- 保留左侧项目列表、中间 Agent/对话区、右侧设备预览的核心布局。
- 右侧增加“预览 / 代码”页签；代码区只读展示 `index.html`、`styles.css`、`app.js`，提供复制单文件能力。
- 预览使用无同源权限的 iframe；切换桌面/移动设备仍保留。
- 生成中禁用重复提交、保留输入、展示当前阶段；刷新后继续读取同一 RUNNING run，不重复调用模型。
- 失败时展示面向用户的失败原因、失败阶段和“重新生成”；上一成功版本继续可访问。
- 生成来源只允许 `workers_ai/SUCCESS`、`deterministic/SUCCESS` 或失败终态。deterministic 仅允许需求对齐的已验证本地编译器；不允许通用无关模板。

## 4. 本期范围

- `CodeBundle v1`：依赖零安装、纯前端 HTML/CSS/JavaScript；固定入口文件和总大小限制。
- 一个规划调用、一个代码生成调用、必要时一次定向 repair；QA 使用服务端确定性校验并记录结果。
- 安全 iframe 运行时、CSP、静态危险能力检查和运行错误反馈。
- `Atoms.storage` 的 D1 JSON key-value 桥接、owner/project 授权和容量限制。
- 旧 AppSpec 版本兼容读取；新生成和修改产生 code bundle 版本。
- 计数器为 P0 回归；Todo、计算器、落地页和表单工具组成扩展语义基准。
- 更新 README、架构说明、线上证据和 GitHub Public 仓库。

## 5. 系统边界

- 本仓库负责 UI、Agent 编排、代码包验证、沙箱、存储桥接、D1、版本和部署。
- Cloudflare Workers AI 只负责模型推理，不拥有项目或应用状态。
- Sites/Cloudflare 负责运行环境、AI/D1 binding 与公网入口。
- 生成代码是不可信输入；它不能访问父页面 Cookie、认证头、Worker binding 或服务端密钥。

## 6. 明确不做

- 不执行模型生成的服务器命令、Node/Python/数据库脚本。
- 不安装 npm 包，不支持任意第三方依赖或动态 import。
- 不开放外部网络请求、OAuth、支付、邮件、Webhook 或私密 API。
- 不生成独立后端服务、原生 App 或多页面路由工程。
- 不承诺抵御蓄意构造的所有浏览器 CPU/内存攻击；通过沙箱、静态拒绝、体积和运行门禁降低 Demo 风险。

## 7. 业务与非功能规则

- NFR-001：公网主地址可直接访问，核心流程无需安装本地环境；在线链接和 GitHub 仓库必须可测试。
- NFR-002：构建、类型、lint、单元、API/D1、沙箱交互、浏览器和真实模型证据分层闭环；不能以 HTTP 200 或页面打开替代需求一致性。
- NFR-003：iframe 仅 `allow-scripts`，无 `allow-same-origin`、forms、popups、downloads 或 top-navigation；CSP `default-src/connect-src` 拒绝网络与外链脚本/对象，`form-action/base-uri` 配合 sandbox 限制表单和导航入口；服务端拒绝危险文件、路径和 API。
- NFR-004：审计保存失败阶段、公开错误码、校验路径、模型与耗时，不保存完整 prompt、被拒绝代码、Cookie、Token 或平台异常原文。
- NFR-005：D1 是应用状态事实源；所有状态 API 服务端恢复 owner，拒绝客户端 owner；每项目最多 50 个 key，单 value 8 KiB、总量 64 KiB。
- NFR-006：完整生成 API 目标小于 65 秒；生成中可恢复，超时不得产生迟到版本；真实语义基准至少 5 类且通过率不低于 90%，计数器必须 100% 通过。
