# Atoms AI App Builder Demo PRD

> 状态：`DRAFT`。冻结前不得作为开发完成声明。

## 1. 来源与目标

来源为挑战原文、补充评估维度及 MGX/Atoms 官方帮助材料。目标用户是希望快速验证想法的非技术创作者。最终结果是一款在线可用的 AI 应用生成工作区，而不是静态仿站。

## 2. 用户场景

| Requirement | 用户/前置 | 操作 | 预期结果 | 异常结果 |
| --- | --- | --- | --- | --- |
| FR-001 | 首次访问者 | 进入应用 | 看到简短引导、示例提示词和可直接开始的输入区 | 页面加载失败时可刷新重试（DEC-007） |
| FR-002 | 已进入工作区 | 输入应用需求并开始生成 | 创建项目并显示 Agent 分工与实时阶段 | 空输入不提交；失败可重试（DEC-007） |
| FR-003 | Agent 运行中 | 观察执行过程 | 依次看到产品、架构、设计、工程 Agent 的状态和产出摘要 | 任一步失败不覆盖已有成功版本（DEC-007） |
| FR-004 | 构建完成 | 操作右侧预览 | 生成应用具有真实按钮、筛选、表单或状态交互 | 预览异常时保留可读方案并允许恢复（DEC-007） |
| FR-005 | 已完成至少一次构建 | 刷新或重新打开页面 | 项目、消息和版本从服务端恢复 | 数据读取失败显示明确错误（DEC-007） |
| FR-006 | 已有生成版本 | 提出颜色、布局或功能修改 | 创建新版本，预览更新；版本菜单可切换新旧结果 | 不支持的修改给出可解释反馈，错误版本号不改变当前状态（DEC-007） |

## 3. 页面与交互

- 左侧：品牌、项目列表和新建项目。
- 中间：对话、Agent 执行轨迹、建议提示词和输入框。
- 右侧：生成应用预览、设备尺寸切换、刷新、版本选择和发布状态。
- 空状态突出一句话输入；执行态显示可读的阶段进度；完成态将预览作为第一视觉焦点；错误态保留用户输入并提供重试。

## 4. 本期范围

覆盖 FR-001 至 FR-006；使用服务端持久化；发布到可测试在线地址；提供项目内交付材料和真实运行证据。

## 5. 跨系统/跨仓边界

单仓交付。外部只依赖 Sites 的 D1 与托管能力；不连接真实第三方账号。

## 6. 明确不做

不承诺任意代码生成、外部模型调用、真实 GitHub/支付/广告集成、多人协作和企业权限。

## 7. 业务规则

- NFR-001 完成度：所有主流程必须真实可操作，构建和类型检查通过，刷新恢复可验证。
- NFR-002 工程思维：采用可解释的规则生成器、有限模板和版本化数据模型，避免引入外部模型密钥与不可控成本。
- NFR-003 用户体验：首次进入无需学习文档，输入、执行、预览和错误反馈清晰顺畅；窄屏仍可访问关键内容。
- NFR-004 创新性：Agent 输出直接影响生成方案；支持“继续修改 + 版本对比”作为延展能力。
- NFR-005 可交付性：在线地址可访问，PRD、方案、测试证据、限制与回滚记录完整。
- NFR-006 调研可追溯：交付材料记录官方帮助与公开产品体验如何影响设计，事实与设计选择分开管理。
- NFR-007 资源取舍：优先保证初始化、生成、交互预览和持久化；延展能力只选择“继续修改与版本历史”这一组闭环，不扩展第三方集成。
